# Fuzz Properties — Sherwood Protocol

Generated by `fizz` Step 9 from five parallel discovery agents (138 candidates,
deduplicated and curated to the set below). Each entry has a stable Spec ID.
`[ ]` = not yet implemented, `[x]` = implemented in `test/fizz/Properties.sol`.

**Guarantee tags drive triage of any violation:**

- **SHOULD-HOLD** — explicitly guaranteed by docs/spec, an ERC clause, or an exact
  accounting identity. A violation is a **confirmed bug**.
- **EXPLORATORY** — inferred from code or general DeFi patterns. A violation is a
  **lead for human review**, not automatically a bug.

Scope: `SyndicateVault`, `VaultWithdrawalQueue`, `SyndicateGovernor`,
`GuardianRegistry`, `StakedWood`, `ExposureLedger`, `ChallengeGame`, `TokenCourt`,
`TierRegistry`, `ProposerBondEscrow`. Strategies, adapters, the oracle and
`SyndicateFactory` are out of scope for this campaign.

---

## Global properties (`GL-NN`)

Checked after every call sequence.

### Conservation

- [x] **GL-01** `SHOULD-HOLD` — `wood.balanceOf(ChallengeGame) >= bondedWood + unclaimedWood`.
  Verbatim NatSpec on the contract header. Maintained across six write sites and
  three terminal paths with no on-chain assertion (x-ray I-1).
- [ ] **GL-02** `SHOULD-HOLD` — `wood.balanceOf(GuardianRegistry) == slashAppealReserve`.
  The registry custodies no other WOOD; `fundSlashAppealReserve` / `refundSlash`
  are the only two writers, each paired 1:1 with a real transfer.
- [ ] **GL-03** `SHOULD-HOLD` — `wood.balanceOf(ProposerBondEscrow) >= Σ locked bond amounts`.
  The escrow keeps no aggregate of its own, so this needs a ghost (x-ray I-24 shape).
- [ ] **GL-04** `SHOULD-HOLD` — `wood.balanceOf(TierRegistry) >= totalBondedWood`
  (valid while WOOD is the only configured bond token, which the harness enforces).
- [x] **GL-05** `SHOULD-HOLD` — Σ live redeem-request amounts == `queue.pendingShares()`.
- [x] **GL-06** `SHOULD-HOLD` — Σ live deposit-request amounts == `queue.pendingDepositAssets()`.
- [x] **GL-07** `SHOULD-HOLD` — Σ stamped-but-unclaimed redeem amounts == `queue.stampedUnclaimedShares()`.
  This is the exact set `SyndicateVault._pricingSupply` excludes (x-ray I-17).
- [ ] **GL-08** `SHOULD-HOLD` — `queue.reservedAssets()` == Σ over pids of `_pidReserved[pid]`.
  No public getter for `_pidReserved`; requires a ghost mirroring both write sites.
- [x] **GL-09** `SHOULD-HOLD` — Σ actor vault-share balances + queue-escrowed shares == `vault.totalSupply()`.
  Standard no-phantom-mint check, specialised to the one non-wallet share holder.
- [ ] **GL-10** `SHOULD-HOLD` — Σ actor asset balances + `asset.balanceOf(vault)` == total minted asset supply.
  `asset` never leaves the {actors, vault} set in the fuzzed surface.
- [x] **GL-11** `SHOULD-HOLD` — `StakedWood.totalGuardianStake` == Σ `stakedAmount` over
  guardians with `unstakeRequestedAt == 0`. The conditional decrement in `_slashOne`
  (active-only) is the subtle edge (x-ray I-4).
- [ ] **GL-12** `SHOULD-HOLD` — per guardian, `ledger.openExposureUsd(g)` == Σ of that
  guardian's per-proposal recorded exposure via `approversOf` (x-ray I-5, first clause).
- [ ] **GL-13** `SHOULD-HOLD` — per guardian, pledged-basis total == Σ per-proposal
  `pledgedOf` entries. `_livePledgedUsd` has no accessor; needs a ghost (x-ray I-5, second clause).
- [x] **GL-14** `SHOULD-HOLD` — while a challenge is live, Σ contributor amounts ==
  `challengeOf(id).counterBondWood` (x-ray I-6).

### Counts and state consistency

- [x] **GL-15** `SHOULD-HOLD` — `governor.getActiveProposal() != 0` iff exactly one
  proposal is in state `Executed`, and it is that one. The load-bearing
  one-live-strategy rule (x-ray G-1/G-2).
- [x] **GL-16** `SHOULD-HOLD` — `openProposalCount()` == count of proposals in
  {Draft, Pending, GuardianReview, Approved, Executed}.
- [x] **GL-17** `SHOULD-HOLD` — `game.liveChallengeCountOf(gov, pid)` == count of
  challenges against that key with status Filed or Disputed. This refcount gates
  the ledger's coverage freeze.
- [x] **GL-18** `SHOULD-HOLD` — `ledger.frozenCoverageCount()` == number of keys
  reporting `isCoverageFrozen` true.
- [ ] **GL-19** `SHOULD-HOLD` — a guardian never appears in both the approver and
  blocker set of the same review. Explicitly marked LOAD-BEARING in source.
- [ ] **GL-20** `SHOULD-HOLD` — approver-array length == count of guardians whose
  recorded vote is Approve (and the blocker mirror).
- [ ] **GL-21** `SHOULD-HOLD` — at most one live challenge per (review key, challenger) (x-ray G-44).
- [ ] **GL-22** `SHOULD-HOLD` — `registry.paused()` is false iff `pausedAt == 0`.
  A drifted `pausedAt` corrupts the next cycle's deadman delay.

### One-shot latches and terminality

- [x] **GL-23** `SHOULD-HOLD` — a terminal `proposal.state` (Settled/Cancelled/Expired/Rejected)
  never changes again (x-ray I-21 consequence).
- [ ] **GL-24** `SHOULD-HOLD` — proposal state transitions only along the legal edge set
  `Draft→{Pending,Cancelled,Expired}`, `Pending→{GuardianReview,Approved,Rejected,Expired,Cancelled}`,
  `GuardianReview→{Approved,Rejected,Expired,Cancelled}`, `Approved→{Executed,Expired,Cancelled}`,
  `Executed→{Settled}`.
- [ ] **GL-25** `SHOULD-HOLD` — `proposal.executedAt` is a one-shot latch, never reset or overwritten.
  `ChallengeGame.file` and `TokenCourt.refer` both derive snapshots from it.
- [x] **GL-26** `SHOULD-HOLD` — a challenge reaches exactly one terminal status and never
  changes after (x-ray I-25).
- [ ] **GL-27** `SHOULD-HOLD` — challenge status edges are exactly
  `Filed→{Disputed,Settled}`, `Disputed→{Settled,Failed,Inconclusive}`.
- [ ] **GL-28** `SHOULD-HOLD` — `_convicted[reviewKey]` is one-shot; a second `file()`
  against a convicted key always reverts.
- [ ] **GL-29** `SHOULD-HOLD` — `swood.verdictSlashed(caseKey, approver)` is one-shot
  (x-ray I-27). Twin of GL-28 across the contract boundary.
- [x] **GL-30** `SHOULD-HOLD` — a court case's phase goes `Voting→Resolved` once, never back.
- [x] **GL-31** `SHOULD-HOLD` — `voteOf[caseId][voter]` is one-shot: NatSpec says
  "NO VOTE CHANGES" (x-ray I-26).
- [ ] **GL-32** `SHOULD-HOLD` — `caseOfChallenge[game][challengeId]` is set once.
- [ ] **GL-33** `SHOULD-HOLD` — `isAccused[caseId][addr]` is never cleared mid-case.
- [x] **GL-34** `SHOULD-HOLD` — a queue request's `claimed` and `cancelled` are mutually
  exclusive and each one-shot.
- [ ] **GL-35** `SHOULD-HOLD` — `_settlePrice[pid].stamped` is one-shot (x-ray G-19).
- [x] **GL-36** `SHOULD-HOLD` — a bond record goes `0 → proposer → 0` via exactly one of
  release XOR forfeit (x-ray I-24).
- [ ] **GL-37** `SHOULD-HOLD` — `Review.opened` and `Review.resolved` are each one-shot.
- [ ] **GL-38** `SHOULD-HOLD` — a TierRegistry bond's `releasableAt` is one-shot per bond
  instance; a fresh bond is a new struct, not a reset.

### Monotonicity

- [x] **GL-39** `SHOULD-HOLD` — `challengeCount`, `caseCount`, `proposalCount` and
  `nextRequestId` never decrease.
- [x] **GL-40** `SHOULD-HOLD` — `challengeableUntil[key]` never decreases. The contract
  leans on this "never shorten" high-water mark in several places.
- [ ] **GL-41** `SHOULD-HOLD` — `EmergencyReview.round` never decreases. It keys the
  anti-replay map for emergency block votes.
- [x] **GL-42** `SHOULD-HOLD` — `vault.highWaterPricePerShare()` is non-decreasing while
  `totalSupply != 0`, and resets to 0 only on a full drain (x-ray I-18;
  `performance-fee/spec.md`: "The mark MUST never decrease").
- [ ] **GL-43** `SHOULD-HOLD` — `_authorizedGovernors` membership only grows.

### Pricing and rounding

- [x] **GL-44** `SHOULD-HOLD` — `convertToAssets(convertToShares(a)) <= a` (ERC-4626).
- [x] **GL-45** `SHOULD-HOLD` — `convertToShares(convertToAssets(s)) <= s` (ERC-4626).
- [ ] **GL-46** `SHOULD-HOLD` — vault pricing supply == `totalSupply() - queue.stampedUnclaimedShares()`.
  No `pricingSupply()` getter; derive via the conversion functions (x-ray I-17).
- [x] **GL-47** `SHOULD-HOLD` — a guardian's age-weighted vote weight never exceeds their
  raw votable stake at the same timestamp (`guardian-staking/spec.md`:
  "Weight MUST never exceed raw stake at the same timestamp").
- [ ] **GL-48** `SHOULD-HOLD` — a historical checkpoint read is stable: once `ts` is past,
  `getPastVotes(g, ts)` returns the same value regardless of later top-ups.
  The spec names "deflation-only drift" as a prior bug class this design fixed.
- [ ] **GL-49** `EXPLORATORY` — per guardian, Σ booked coverage shares across keys
  <= their slashable stake. This is x-ray X-8, flagged On-chain=**No** — the
  mathematical core of E-1 that nothing currently asserts.

### Liveness and economics

- [ ] **GL-50** `EXPLORATORY` — an `Executed` proposal can always reach `Settled` through
  permissionless calls alone, without vault-owner cooperation. If false, a hostile
  proposer can wedge a vault permanently via G-1.
- [ ] **GL-51** `EXPLORATORY` — under every reachable parameter configuration,
  `game.honestFilingNetPayoffBps()` stays non-negative. The contract *reports* the
  break-even condition but does not enforce it (x-ray E-4).

## Specific properties (`SP-NN`)

Asserted inside the handler that performs the call.

### Postconditions

- [ ] **SP-01** `SHOULD-HOLD` — after `executeProposal(pid)`: state is `Executed`,
  `getActiveProposal() == pid`, capital snapshot set, `executedAt == block.timestamp`.
  The most load-bearing postcondition in the protocol.
- [ ] **SP-02** `SHOULD-HOLD` — after `settleProposal` / `unstick` /
  `finalizeEmergencySettle`: state is `Settled`, `getActiveProposal() == 0`,
  capital snapshot deleted, `openProposalCount` decreased by exactly 1.
- [ ] **SP-03** `SHOULD-HOLD` — after `file()`: status is `Filed`, `bondedWood` increased
  by exactly the bond, live count for the key incremented by 1.
- [ ] **SP-04** `SHOULD-HOLD` — after the pool-completing `dispute()`: status flips
  `Filed→Disputed` and `counterBondWood == bondWood` exactly.
- [ ] **SP-05** `SHOULD-HOLD` — after `finalize(caseId)`: phase is `Resolved`,
  `finalizedAt == block.timestamp`, and the challenge is no longer Filed/Disputed
  (or the only swallowed revert was `WrongStatus`).
- [ ] **SP-06** `SHOULD-HOLD` — after `stampSettlement`: `_pidReserved[pid]`,
  `reservedAssets` and `stampedUnclaimedShares` all move together, sourced from the
  same `redeemShares`.
- [ ] **SP-07** `SHOULD-HOLD` — after a redeem `claim`: request marked claimed,
  `pendingShares` and `stampedUnclaimedShares` each decrease by exactly the amount.
- [ ] **SP-08** `SHOULD-HOLD` — `_slashOne` postcondition: if the guardian was active,
  `totalGuardianStake` decreases by exactly the slashed amount; if unstake-requested,
  it is unchanged (already excluded at request time). x-ray I-4's flagged edge.

### Round trips

- [ ] **SP-09** `SHOULD-HOLD` — `deposit(a)` then immediately `redeem(all minted shares)`
  never returns more than `a`.
- [ ] **SP-10** `SHOULD-HOLD` — `mint(s)` then `redeem(s)` never yields a net asset gain
  (previewMint rounds up, convertToAssets rounds down).
- [ ] **SP-11** `SHOULD-HOLD` — a redeem claim pays exactly
  `floor(shares * num / den)` at its own proposal's stamped price — never a
  later proposal's (the redeem branch is the strict one; deposit is the
  documented exception, x-ray X-13).
- [ ] **SP-12** `SHOULD-HOLD` — a deposit claim mints exactly `floor(assets * den / num)`.
- [ ] **SP-13** `SHOULD-HOLD` — `cancel()` before stamping returns the escrowed amount exactly.
- [ ] **SP-14** `SHOULD-HOLD` — the final claim on a settled pid releases the *entire*
  remaining `_pidReserved[pid]`, including `floor(Σ) − Σfloor` dust. Source NatSpec
  warns stranded dust would eventually brick `executeGovernorBatch`.
- [ ] **SP-15** `SHOULD-HOLD` — `requestUnstakeGuardian` then `cancelUnstakeGuardian`
  restores `totalGuardianStake` and `stakedAmount` bit-for-bit.
- [ ] **SP-16** `SHOULD-HOLD` — `prepareOwnerStake` then `cancelPreparedStake` returns
  exactly the prepared amount.
- [ ] **SP-17** `SHOULD-HOLD` — `recordApproval` then `releaseApproval` restores every
  coverage accumulator to its pre-approval value (x-ray I-5).
- [ ] **SP-18** `SHOULD-HOLD` — `freezeCoverage` then `unfreezeCoverage` restores every
  approver's frozen-commitment counter.
- [ ] **SP-19** `SHOULD-HOLD` — `lockBond` then `releaseBond` returns exactly the locked amount.
- [ ] **SP-20** `SHOULD-HOLD` — `lockBond` then `forfeitBond` splits exactly:
  `fee + burned == amount`, `fee <= 20%` of amount.
- [ ] **SP-21** `SHOULD-HOLD` — propose → cancel → `reclaimProposerBond` is economically free.

### Fee and slash arithmetic

- [ ] **SP-22** `SHOULD-HOLD` — every wei of management fee charged is accounted for by
  recipient deltas plus newly-escrowed `_unclaimedFees` — none minted or lost.
- [ ] **SP-23** `SHOULD-HOLD` — same for the performance fee, including the co-proposer
  split loop (the only leg with real branch/rounding logic).
- [ ] **SP-24** `SHOULD-HOLD` — fee splits sum to exactly the total fee, with the agent
  receiving the remainder rather than a separately-floored share.
- [ ] **SP-25** `SHOULD-HOLD` — the management fee is consumed *before* the high-water
  comparison, so the performance base is computed on post-management-fee assets.
  Source calls this ordering load-bearing.
- [ ] **SP-26** `SHOULD-HOLD` — a slash removes exactly `floor(slashable * slashBps / 10_000)`,
  never more than the live stake.
- [ ] **SP-27** `SHOULD-HOLD` — the stake-age re-anchor on top-up rounds *toward now*
  (ceiling), never granting free age (`guardian-staking/spec.md`:
  "Rounding MUST never grant free age").
- [ ] **SP-28** `SHOULD-HOLD` — counter-bond refunds never pay out more than the pool.

### Snapshot integrity

- [ ] **SP-29** `SHOULD-HOLD` — shares acquired at or after a proposal's
  `snapshotTimestamp` contribute zero weight to that proposal
  (`syndicate-governor/spec.md`: `snapshotTimestamp = block.timestamp - 1`
  "closing the same-block flash-delegate window").
- [ ] **SP-30** `SHOULD-HOLD` — a review's block-quorum denominator and threshold are
  snapshotted at open and never re-read live at resolution.
- [ ] **SP-31** `EXPLORATORY` — the veto denominator is frozen at Pending-entry; a
  mid-proposal supply change cannot move the bar.
- [ ] **SP-32** `SHOULD-HOLD` — every burn/fee rate used to price a challenge equals the
  value pinned at filing, not the live parameter (x-ray I-15).

### Adversarial

- [ ] **SP-33** `SHOULD-HOLD` — a guardian who is an unresolved approver on a live review
  cannot complete `claimUnstakeGuardian`. The cooldown (`coolDownPeriod >= reviewPeriod`)
  is the only thing covering this; `claimUnstakeGuardian` has no visibility into
  review state, and `resolveReview` is permissionless with no deadline.
- [ ] **SP-34** `EXPLORATORY` — a guardian's coverage cannot be kept pinned indefinitely
  by a chain of self-funded challenges whose per-cycle cost does not grow.
- [ ] **SP-35** `EXPLORATORY` — the participation floor used by `finalize` is the value in
  force when voting closed, not one an owner set afterwards.
- [ ] **SP-36** `EXPLORATORY` — an emergency-settle batch cannot move non-`asset()` tokens
  without a per-call cap. The net-outflow cap is denominated only in `asset()`.
- [ ] **SP-37** `EXPLORATORY` — the co-proposer dust-pad erodes the lead proposer's
  nominal 10% floor (G-11) by at most 1 wei per co-proposer.
- [ ] **SP-38** `EXPLORATORY` — `requiredCoverage`'s per-call flooring under-prices
  coverage only within a bounded total, never compounding with call count.

## Deliberately NOT asserted

Recorded so a future contributor does not "fix" these into properties:

- **`ExposureLedger._settled[key]` is not an idempotency gate.** `settleCoverage`
  is documented re-runnable; asserting one-shot here would be wrong (x-ray I-29).
- **`StakedWood.flushBurn` is intentionally re-runnable**, not a one-shot latch.
- **`_demote` clearing the whole adapter allowlist is deliberately over-broad** —
  the source calls it "the correct direction of error".
- **Certification and fund-routing allowlisting are independent axes** — asserting
  `certify ⇒ isAdapterAllowed` would test a property the design explicitly rejects.
- **Slow-bleed extraction across many proposals (x-ray E-3)** is a stated, accepted
  residual for v1. Not a finding.

## Known gaps in this catalog

- **`stakedAt` has no public accessor.** Properties needing the stake-age anchor
  (SP-27, and a stricter form of GL-47) require a `StakedWoodHarness` exposing it.
- **Protocol-wide covered-TVL cap.** `requireWithinCoveredTvlCap` checks one
  proposal against `coveredTvlCapUsd` with no running accumulator, so N vaults can
  each sit just under the cap. Not fuzzable here — the harness deploys a single
  vault — but worth a look independent of this campaign.
- **Live strategy PnL is invisible to share price.** `totalAssets()` is
  `balanceOf(asset) − reservedQueueAssets()` with no router term;
  `openspec/specs/epoch-nav/spec.md` still describes a `PriceRouter` NAV mechanism
  that `SyndicateFactory` marks `__deprecated_priceRouter`. Spec/code drift, not a
  fuzzable property.
