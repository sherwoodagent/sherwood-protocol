# Dimensional Units

This file defines the dimensional vocabulary for this codebase.
Generated by the dimensional-analysis plugin.

> **A SNAPSHOT, NOT A SPEC.** Derived from `src/` at commit `6092115`
> (2026-07-28) by reading the code, not from any design document. Where it
> disagrees with the source, the source wins and this file is stale.
>
> It is deliberately a standalone document rather than inline annotations. The
> full annotation pass touched 34 files and ~2,200 lines; that was kept out of
> the tree because unit claims scattered through code age silently — and three
> such stale claims were found during the very review that produced this file:
> a "no vault consumes this yet" that was false, a "dimensionless" value that
> was not, and a pre-flight naming an error that had been renamed. A single
> dated document can be checked in one place and discarded when it rots.
>
> **What it is for.** The bugs this vocabulary was built to expose all share one
> shape: two quantities of identical Solidity type and precision where only one
> is correct, with no compiler check between them. `USD18{reserved}` vs
> `USD18{allocated}`; `WOOD{votable}` vs `WOOD{liability}`; the raw WOOD scalar
> vs the composed price; vote weight vs raw stake. Reach for this when adding
> arithmetic that crosses one of those boundaries.
>
> Note: `MoonwellSupplyStrategy` and its adapter are referenced below but are
> slated for removal from the repo.

Scope source: `DIMENSIONAL_SCOPE.json` (`discoverer_focus_files`, 29 CRITICAL/HIGH
files, walked in `recommended_discovery_order`).

Notation: `<PREFIX>{<unit>}`, e.g. `D18{USD}` is a USD amount carried as an
integer scaled by `1e18`. A brace tag after a unit (`USD18{reserved}`) marks a
SEMANTIC subtype: same integer scale, NOT interchangeable.

## Base Units

- `{USD}` — United States dollar value. Always carried as `D18{USD}` in the
  guardian/insurance layer. Produced only by `ExposureLedger.coverageUsd`
  (`src/ExposureLedger.sol:627`) and `_slashableBondUsd` (`:378`).
  Sources: `coverageUsd`, `coveredTvlCapUsd`, `openExposureUsd`,
  `slashableBondUsd`, `liabilityUsd`, `allocatedUsd`, `frozenCoverageUsd`,
  `_committedUsd`, `_buckets`, `RecordedExposure.usd` (`uint192`).
  Confidence: HIGH.

- `{WOOD}` — WOOD governance-token wei, 18 decimals, plain ERC20 (no
  fee-on-transfer, no rebasing — asserted in `CompensationEscrow` header).
  Sources: `Guardian.stakedAmount`, `totalGuardianStake`, `minGuardianStake`,
  `minOwnerStake`, `bondWood`, `counterBondWood`, `bondedWood`, `forfeitedWood`,
  `reservedRewards`, `panelBondWood`, `appealBondWood`, `badFaithBondWood`,
  `panelRewardWood`, `poolTokens`, `unbondingPoolTokens`, `totalDelegatedStake`,
  `totalActiveDelegatedStake`, `Case.proceeds`, `Case.redeemed`, `totalEscrowed`.
  Confidence: HIGH.

- `{ASSET}` — a vault's underlying ERC-20 amount in THAT ASSET'S OWN decimals
  (USDC 6, WETH 18). Never normalized on its own; only `coverageUsd` lifts it to
  `D18{USD}` using the cached `AssetFeed.assetDecimals`.
  Sources: `SyndicateVault.totalAssets`, `asset()` balances,
  `SyndicateGovernor` `envelope.maxCapital` and `requiredCoverage`,
  `LeveragedAeroFees.navPre` / `protocolUsdc`, `VaultWithdrawalQueue` deposit
  escrow, strategy `nav()`.
  Confidence: HIGH.

- `{SHARE}` — ERC-4626 vault shares of a `SyndicateVault`. Share decimals are
  `assetDecimals + _decimalsOffset()` and `_decimalsOffset()` RETURNS THE
  ASSET'S DECIMALS (`src/SyndicateVault.sol:696`, cached at `:212`), so
  **share decimals = 2 x assetDecimals** — 12 dp on USDC, not 18+assetDecimals.
  Corroborated by `LeveragedAeroFees` header ("vault shares, 12 dp") and
  `LeveragedAerodromeCLStrategy.SHARES_VIRTUAL_OFFSET = 1e6`.
  Sources: `totalSupply`, `convertToShares` / `convertToAssets`, `previewX`,
  `feeShares`, `VaultWithdrawalQueue._pendingShares` / `_pidRedeemShares`.
  Confidence: HIGH.

- `{POOLSHARE}` — delegation-pool shares in `StakedWoodDelegation`. ERC-4626-style
  but NOT a vault share and NOT WOOD. Two disjoint pools, whose shares are also
  not interchangeable with each other:
  `poolShares` / `delegationShares` (live) and `unbondingPoolShares` /
  `unbondingShares` (unbonding escrow).
  Confidence: HIGH.

- `{TOK}` — a generic external ERC-20 amount in its own `decimals()`
  (strategy basket allocations, AMM reserves, cToken balances, LP tokens).
  Sources: `PortfolioStrategy._tokenDecimals`, `AerodromeLPAdapter` reserves /
  `lpBal`, `ICToken.balanceOf` (mTokens are 8 dp), Uniswap `amountIn` /
  `amountOutMinimum`.
  Confidence: HIGH.

- `{s}` — seconds. Timestamps, windows, durations, cooldowns, ages.
  Sources: `block.timestamp`, `epochLength`, `epochGenesis`, `challengeWindow`,
  `reviewPeriod`, `coolDownPeriod`, `maturationPeriod`, `autoSlashDelay`,
  `disputeTimeout`, `panelWindow`, `badFaithWindow`, `appealWindow`,
  `residueWindow`, `strategyDuration`, `executeBy`, `voteEnd`, `reviewEnd`,
  `maxDelay`, `gracePeriod`, `SECONDS_PER_YEAR`, `dt`, `elapsed`, `age`.
  Confidence: HIGH.

- `{bps}` — basis points, denominator `BPS_DENOMINATOR = 10_000` (declared
  independently in `ExposureLedger`, `GuardianRegistry`, `ChallengeGame`,
  `Court`, `StakedWoodDelegation`; `PriceRouter.MAX_HAIRCUT_BPS`;
  `TierRegistry.FULL_NOTIONAL_BPS`).
  Sources: `proposerBondBps`, `woodHaircutBps`, `maxDelegatedSlashBps`,
  `minSlashBps`, `maxSlashBps`, `ageFloorBps`, `blockQuorumBps`,
  `LATE_VOTE_LOCKOUT_BPS`, `SUPERMAJORITY_BPS`, `MAX_REFUND_PER_EPOCH_BPS`,
  `challengerBondBps`, `forfeitBurnBps`, `settleBurnBps`, `participationFloorBps`,
  `MAX_COMMISSION_BPS`, `haircutBps`, `extractableBoundBps`, `maxDrawdownBps`,
  `managementFeeBps`, `performanceFeeBps`, `protocolFeeBps`, `agentFeeBps`,
  `minBufferBps`, `maxSlippageBps`.
  Confidence: HIGH.

- `{1}` — dimensionless scalar with no bps denominator.
  Sources: `kNumerator`, `delegatedWeightCapX`, `epoch` index, `MAX_SCAN_BUCKETS`,
  `MAX_PANEL_SIZE`, `MAX_APPROVERS_PER_PROPOSAL`, `_frozenCommitments` (a COUNT,
  deliberately not a USD sum — `src/ExposureLedger.sol:243`), `_frozenKeyCount`,
  `envelopeTier` / `quorumTierThreshold` (ordinal 0..3).
  Confidence: HIGH.

## Derived Units

### The reservation / allocation split (first-class; two prior bugs)

Both are `D18{USD}` `uint256` and both live in `ExposureLedger`. They are NOT
interchangeable. Summing reservations where an allocation is meant over-states
exposure by a factor that GROWS WITH THE APPROVER COUNT.

- `USD18{reserved}` — RESERVATION. What a guardian booked at approve time:
  `min(free budget, the proposal's FULL required coverage)`
  (`ExposureLedger.recordApproval`, `src/ExposureLedger.sol:766`).
  Every approver reserves up to the whole need, so
  `sum(reserved) = A x needUsd` for A well-funded approvers — reservations SUM
  ABOVE the need.
  Carried by: `RecordedExposure.usd`, `_committedUsd[key]`, `_buckets`,
  `approversOf(...).committedUsd`, `openExposureUsd`, and the `haveUsd` sum
  inside `requireApproveQuorum` (`:1048`, correctly reservation-typed —
  summing allocations there would be circular and fail on truncation dust).
  Composition: `min({USD18{budget}}, {USD18{need}})`.
  Confidence: HIGH.

- `USD18{allocated}` — ALLOCATION. What a guardian actually owes: the need split
  pro-rata by EFFECTIVE bond, so `sum(allocated) <= needUsd` (rounds down;
  `settleCoverage` hands the truncation residue to the first holder).
  Produced by `_allocate` (`:1413`); read via `allocatedUsd` (`:1201`),
  `slashBpsFor` (`:1111`) and `liabilityUsd` (`:1228`).
  Composition: `USD18{effective} * USD18{need} / USD18{effectiveTotal}`.
  Confidence: HIGH.

  Known substitution bugs this distinction exists to catch, both recorded in
  source comments: `ChallengeGame.file()` used to sum `approversOf` (the
  RESERVATION) to size a challenger bond while every slash prices the
  ALLOCATION (`src/ChallengeGame.sol:476-497`); and `slashBpsFor`'s note that
  slashing the reservation "would take the whole coverage from EVERY approver"
  (`src/ExposureLedger.sol:1126`).

- `USD18{effective}` — `min(USD18{reserved}, USD18{bond})` for one guardian: what
  it can ACTUALLY pay, not what it pledged. The shared basis of
  `requireApproveQuorum`, `allocatedUsd`, `slashBpsFor` and `settleCoverage`.
  Composition: `min({USD18{reserved}}, {USD18{bond}})`. Confidence: HIGH.

- `USD18{effectiveTotal}` — `sum` of `USD18{effective}` over a proposal's
  approvers (`_effectiveTotal`, `:1251`). The pro-rata DENOMINATOR. Using raw
  `_committedUsd` here instead is a known wrong substitution. Confidence: HIGH.

- `USD18{open}` — `openExposureUsd(guardian)`: sum of that guardian's epoch
  buckets still inside their challenge window. Reservation-typed BEFORE
  `settleCoverage`, allocation-typed after (settlement rewrites the buckets).
  Confidence: HIGH.

- `USD18{need}` — a proposal's required coverage in dollars,
  `coverageUsd(asset, requiredCoverage)`. Re-derived from the LIVE feed at each
  read, so two reads at different timestamps are not the same number.
  Confidence: HIGH.

- `USD18{bond}` — `slashableBondUsd(g)` =
  `(ownStake + delegatedInbound * maxDelegatedSlashBps / 10_000) * priceX8 / 1e8`.
  Composition: `{WOOD} * D8{USD/WOOD} / 1e8`. Confidence: HIGH.

- `USD18{budget}` — `kNumerator * USD18{bond}`, the per-guardian batching cap;
  `free = budget - USD18{open}` (`:746-764`).
  Composition: `{1} * USD18{bond}`. Confidence: HIGH.

- `USD18{liability}` — `min(USD18{need}, USD18{effectiveTotal})`, the cohort's
  total real exposure on one proposal. The basis a challenger bond is sized
  against. Confidence: HIGH.

### Prices and oracle reads

- `D8{USD/WOOD}` (`priceX8`) — WOOD price normalized to 8 decimals via
  `(uint256(answer) * 1e8) / (10 ** f.feedDecimals)` then multiplied by
  `woodHaircutBps/10_000` (`src/ExposureLedger.sol:352`, `_haircut` at `:371`).
  `woodPriceX8()` = feed-first with `woodUsdPriceX8` as the degraded fallback.
  CAUTION: `ChallengeGame.file` reads the RAW governance scalar
  `exposureLedger.woodUsdPriceX8()` (`src/ChallengeGame.sol:511`), not the
  haircut/feed-composed `woodPriceX8()` — a different quantity of the same
  precision. Confidence: HIGH.

- `Dn{USD/TOK}` — a raw Chainlink `answer` at the feed's own `decimals()`
  (`AssetFeed.feedDecimals`, `PortfolioStrategy._priceDecimals`,
  `ChainlinkReader.readUsd` returning `(price, decimals)`). NEVER assume 18 or 8:
  `PortfolioStrategy` explicitly supports 8 (tokenized stocks) and 18 (crypto),
  and `LeveragedAeroValuation._readUsd8` fail-closes with `FeedDecimalsMismatch`
  unless the feed is exactly 8. Confidence: HIGH.

- `D8{USD/ASSET}` — leg prices inside `LeveragedAeroValuation`
  (`USD_FEED_DECIMALS = 8`). Confidence: HIGH.

- `D18{USD/TOK}` (`PRICE_PRECISION = 1e18`) — `PortfolioStrategy`'s nominal price
  scale. Note the Sherlock #21/#29 fix: real conversions use
  `10 ** (tokenDecimals + priceDecimals)` vs the cached `assetDecimals`
  (`_tokensToValue` / `_valueToTokens`, `src/strategies/PortfolioStrategy.sol:579`),
  NOT the constant. The constant is a legacy anchor. Confidence: HIGH.

### Rates and ratios

- `{WOOD}/{POOLSHARE}` — delegation pool exchange rate, materialized only inside
  `Math.mulDiv(amount, poolShares, poolTokens)` (mint) and
  `Math.mulDiv(liveShares, poolTokens, poolShares)` (redeem), per pool.
  Six such conversions across the live and unbonding pools. Confidence: HIGH.

- `{ASSET}/{SHARE}` — vault conversion rate. Materialized as the frozen
  settlement pair `num = totalAssets() + 1`, `den = totalSupply() + 10 ** offset`
  (`src/SyndicateVault.sol:1143`), consumed by `VaultWithdrawalQueue` as
  `mulDiv(shares, num, den)`. `num` is `{ASSET}`, `den` is `{SHARE}`.
  Confidence: HIGH.

- `D18{ASSET/SHARE}` (`hwmPerShareX`, `navPerShareX`) — `navPre * 1e18 /
  totalSupply` in `LeveragedAeroFees`. The header calls it "dimensionless,
  1e18-scaled"; dimensionally it is asset-per-share and must not be compared
  across vaults with different asset decimals. Confidence: HIGH.

- `D18{ASSET/CTOKEN}` (`exchangeRateStored`) — Compound/Moonwell rate, applied as
  `cBal * rate / 1e18` (`MoonwellSupplyAdapter:42`, `LeveragedAeroValuation:190`).
  Note the true Compound scale is `10**(10 + underlyingDecimals)`, which
  coincides with the 1e18 divisor only because `cBal` is 8 dp; flagged as
  MEDIUM confidence for downstream annotation.

- `{bps}/{s}` implied — the management fee is `managementFeeBps * dt / (10_000 *
  SECONDS_PER_YEAR)`, i.e. an annualized `{bps}` divided by `{s}` and
  re-multiplied by elapsed `{s}` to yield `D18{1}` (`feeRateX`). Confidence: HIGH.

- `bps{slash}` — per-approver slash rate, `ceil(USD18{allocated} * 10_000 /
  USD18{bond})`, clamped to `10_000` (`slashBpsFor`, `:1163`). Rounds UP toward
  the protocol. Consumed positionally by `StakedWood.slashToEscrow`; positional
  alignment with the approver array is load-bearing. Confidence: HIGH.

- `bps{age}` — `_ageFactorBps`, linear ramp from `ageFloorBps` at age 0 to
  `10_000` at `maturationPeriod` (`src/StakedWood.sol:718`). Confidence: HIGH.

### Weights and snapshots

- `WOOD{voteWeight}` — `getPastVotes` = aged own stake + delegated inbound capped
  at `delegatedWeightCapX * agedOwn` (`src/StakedWood.sol:741`). WOOD-scaled but
  NOT spendable WOOD, and NOT the slash basis. Confidence: HIGH.

- `WOOD{liability}` vs `WOOD{votable}` — two distinct checkpoint traces on the
  same guardian. `_liabilityCheckpoints` is not zeroed by
  `requestUnstakeGuardian`; `_stakeCheckpoints` is. `_slashOne` takes
  `Math.max` of the two (`src/StakedWood.sol:1642`). Substituting the votable
  trace for the liability trace is the PR #25 F1b bug. Confidence: HIGH.

- `SHARE{votes}` — vault ERC20Votes weight at a past timestamp, the
  compensation apportionment numerator: `proceeds * votes / snapshotSupply`
  yields `{WOOD}` (`CompensationEscrow`, `Case.snapshotSupply` cached at open).
  Composition: `{WOOD} * {SHARE} / {SHARE}`. Confidence: HIGH.

### Time-derived

- `{epoch}` — dimensionless bucket index, `(block.timestamp - epochGenesis) /
  epochLength`. THREE INDEPENDENT EPOCH CLOCKS exist and are not comparable:
  `ExposureLedger.epochLength` (immutable, 28d spec), `GuardianRegistry`/
  `StakedWoodDelegation.EPOCH_DURATION = 7 days`. Confidence: HIGH.

- `{1/s}` — any rate per second (fee accrual, vesting `elapsed / duration`).
  Confidence: MEDIUM.

### AMM fixed-point

- `Q96{sqrt(tok1/tok0)}` — `sqrtPriceX96` / `sqrtRatioX96`, `uint160`, scale
  `2**96` (`LiquidityAmounts.Q96`, `TickMath`, `ISlipstream`, swap adapters).
  Confidence: HIGH.

- `{L}` — Uniswap/Slipstream liquidity, `uint128`. Composition:
  `sqrt({tok0} * {tok1})`; combines with `Q96{sqrt(...)}` to produce `{TOK}`
  amounts. Confidence: HIGH.

- `{tick}` — `int24` log-space price index; `TickMath` converts
  `{tick} <-> Q96{sqrt(tok1/tok0)}`. Confidence: HIGH.

### Governance / valuation

- `{ASSET}` post-haircut (`PriceRouter._priceOne`, `:102`) — value is returned
  "in the position's underlying units" per `IPriceRouter`, scaled by
  `(10_000 - haircutBps)/10_000`. `valueStrategy` SUMS across positions, which
  is only sound when every adapter for that strategy returns the same
  numeraire. Flagged for human verification: the router never asserts a common
  numeraire. Confidence: MEDIUM.

## Precision Prefixes

- `D6` — `1e6`. USDC/USDT native decimals; `SHARES_VIRTUAL_OFFSET` for a
  USDC vault.
- `D8` — `1e8`. Chainlink USD feeds and the canonical `priceX8` WOOD price;
  cToken/mToken balances.
- `D12` — `1e12`. `SyndicateVault` share decimals when the asset is USDC
  (= 2 x assetDecimals). Derived, never a literal in source.
- `D18` — `1e18`. `WAD`. WOOD wei, all `usd18` coverage/liability/bond values,
  `PRICE_PRECISION`, `hwmPerShareX`, `feeRateX`, Compound `exchangeRateStored`
  divisor, `MIN_COHORT_STAKE_AT_OPEN = 50_000 * 1e18`.
- `BPS` — `10_000`. `BPS_DENOMINATOR` / `MAX_HAIRCUT_BPS` /
  `FULL_NOTIONAL_BPS`. Declared separately in six contracts.
- `Q96` — `2**96` = `0x1000000000000000000000000`. Uniswap V3 / Aerodrome
  Slipstream sqrt-price fixed point.
- `Dn` (dynamic) — `10 ** decimals`, resolved at runtime from
  `IERC20Metadata.decimals()` (`AssetFeed.assetDecimals`,
  `PortfolioStrategy._tokenDecimals`, `_cachedDecimalsOffset`) or from
  `IAggregatorV3.decimals()` (`AssetFeed.feedDecimals`,
  `PortfolioStrategy._priceDecimals`, bounded at 36). Any site that hard-codes
  `1e18` or `1e8` where a dynamic `Dn` is required is a scaling bug — this is
  exactly what Sherlock #21/#29 fixed in `PortfolioStrategy`.
