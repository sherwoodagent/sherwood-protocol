# Pin SyndicateVault's storage layout (issue #148)

## Why

`SyndicateVault` is a UUPS proxy (`_authorizeUpgrade` is factory-gated, `src/SyndicateVault.sol`) and the one contract in this protocol that directly custodies user assets. Every other upgradeable contract with live or eventual mainnet lineage already has a two-layer layout guard: a forge-level slot/offset pin test (`test/GuardianRegistryLayoutPins.t.sol`, `test/governor/GovernorLayoutPins.t.sol`) plus a compiler-emitted golden JSON diffed by `script/check-layout-goldens.sh` (`script/guardian-registry-layout.golden.json`, `script/syndicate-governor-layout.golden.json`, `script/syndicate-factory-layout.golden.json`, `script/staked-wood-layout.golden.json`). `SyndicateVault` has neither. A future field reorder, insertion, or retype in its storage section (`src/SyndicateVault.sol:106-238`) would compile clean, pass the full test suite, and pass CI, then silently corrupt every live vault proxy's storage on the next upgrade — the exact failure mode the other guarded contracts already close off.

## What Changes

- Add `test/VaultLayoutPins.t.sol`, mirroring the established pattern in `test/GuardianRegistryLayoutPins.t.sol` / `test/governor/GovernorLayoutPins.t.sol`: raw `vm.load` slot/offset assertions against a freshly-initialized proxy, covering every top-level storage variable declared in `SyndicateVault` from `_agents` through `__gap`, including the `_laneALockPid` mapping (pinned via its derived slot, the same technique `GuardianRegistryLayoutPinsTest` uses for `vaultOf`) and a positive check that the `__gap[28]` region starts at the correct slot and is unwritten.
- Extend `script/check-layout-goldens.sh` to also `check_contract SyndicateVault script/syndicate-vault-layout.golden.json`, generate the golden via the script's own `--update-golden` path (same mechanism as the other four contracts — no new tooling), and commit the resulting `script/syndicate-vault-layout.golden.json`.
- Add a short natspec/doc note (in the new test file's header, in the same style as the existing layout-pin files' headers) recording the FUTURE convention this issue asks for: a removed `SyndicateVault` field becomes a same-slot placeholder (e.g. `uint256[1] private __deprecated_x;`) or folds into `__gap`, rather than being deleted outright, so a live proxy's storage shape never needs a slot to disappear.
- No `src/` changes. This is purely additive test/CI infrastructure — zero behavior change, zero interface change, zero storage change.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `syndicate-vault`: adds a requirement that the vault's storage layout is pinned by both a forge-level slot test and a golden-JSON CI gate, matching the guarantee already stated for the other upgradeable protocol contracts.

## Impact

- `test/VaultLayoutPins.t.sol` — new file.
- `script/check-layout-goldens.sh` — one new `check_contract` call plus header/comment updates describing the fifth guarded contract.
- `script/syndicate-vault-layout.golden.json` — new golden, generated by the script itself.
- `openspec/specs/syndicate-vault/spec.md` — new requirement via this change's delta spec.
- No `src/` files touched. No collision with any open PR or worktree — verified against `origin/main` immediately before starting this change; nothing else in flight touches `SyndicateVault.sol`'s storage section or `check-layout-goldens.sh`.
